# Implementation changes — 9 November 2026

## Student and advisor authentication

- Students sign in with the campus Student Identity service. The backend verifies the authenticated profile and matching ID before creating a short-lived Internly session.
- Advisors can create an account with their name, email and password, then sign in to the advisor workspace. Passwords are hashed; the server fixes the role to advisor. New advisors have no student assignments or administrator permissions.
- Existing accounts are not silently linked, promoted or reset. Provider credentials and service API keys are not returned to the browser or committed to Git.

## Real workspace and role-based access

- Students can submit internship applications, follow decisions, submit weekly reports for approved internships and read advisor feedback.
- Advisors can view assigned students, review their applications and give progress-report feedback. The backend enforces ownership and assignment on reads and writes.
- Stale-version checks prevent accidental review overwrites. Duplicate applications and duplicate internship/week reports are rejected.
- Local advisor setup and student assignment commands are documented in [STUDENT_ADVISOR_WORKFLOW.md](STUDENT_ADVISOR_WORKFLOW.md).

## Unified interface

- Signed-in students use one workspace: Overview, Opportunities, Applications, Progress reports and Integrations.
- Integration activity and Student Identity are two views of the same Integrations tab. Existing session access remains available without manual operator-token input.
- The homepage redirects signed-in users to their appropriate workspace. Guests see the public opportunity catalogue.
- Opportunity detail links preserve the selected application through student sign-in.
- Removed the old demo dashboard, fake application history, demo progress reports, saved-only demo page and advisor preview. Existing database fixtures remain explicitly labeled; no database records were deleted.

## Other groups' integrations

- Preserve the incoming Team 18 Job Board integration on main, including its public read adapter, normalized listing details and tests.
- Preserve the Team 12 public placements API, Student Identity claims integration and A5 event/webhook integrations.
- Applications submitted in Internly are local internship-management records; they are not submitted to the external Job Board or automatically emitted as A5 webhooks.

## Validation and release scope

- Authentication, authorization, registration, workspace and integration tests run against real local databases and mocked provider responses as appropriate.
- Live local checks cover advisor registration/login/logout, student route redirects, canonical navigation and application return links.
- TypeScript, production build and browser layout checks completed for the unified workspace. The final merged test result is recorded in the commit handoff.
- This commit publishes source and documentation to main. It does not deploy this new role-based version to Vercel or migrate the production workspace tables. Production setup must apply the new authentication fields and workspace migrations before release.

Private environment files, local databases, generated build output, screenshots, temporary files and the friend-provided `docs/internship.md` are excluded from this commit.
